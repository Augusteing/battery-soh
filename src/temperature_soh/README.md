# temperature_soh：温度感知 SOH 估计（最终参赛模型）

## 1. 项目定位

在 `partial_soh`（Scientific Reports 2026 复现，3 通道基线）的基础上，
构建**温度感知**的片段级 SOH 估计模型，作为参赛最终方案。

与基线相比，本模块的增量有三点：

1. **温度通道**：模型输入从 3 通道 `(I, V, Q)` 扩展为 4 通道 `(I, V, Q, T)`；
2. **多数据集训练**：统一 MATR（Severson）+ HUST + SNL 三个 LFP 数据集，
   恒温大数据负责学通用表征，SNL 的 15/25/35°C 数据负责学温度调制；
3. **Arrhenius 物理约束**：把“温度越高、退化越快”的电化学规律作为
   物理先验注入损失函数，弥补变温度样本量不足的问题。

## 2. 数据协议（已与导师方向对齐）

| 数据集 | 电池数 | 温度 | 角色 |
| --- | --- | --- | --- |
| MATR（Severson） | 123（Scientific Reports 口径） | 30°C 恒温 | 通用表征主力 |
| HUST | 77 | 30°C 恒温 | 通用表征 + 放电工况多样性 |
| SNL | 18（LFP） | **15/25/35°C** | 唯一的温度信号来源 |

验证协议：

- **主协议**：按电池留出（SNL 的电池按温度分层留出），
  模拟“比赛数据带温度变化”的真实场景；
- **附加实验**：温度外推（如训练 15/25°C，测试 35°C），
  只作为论文卖点展示，不作为主协议。

## 3. SOH 标签口径（对齐原论文，只加温度通道）

统一采用 Scientific Reports 2026 原论文口径：

```
SOH(k) = Q_charge(k) / Q_nominal（1.1 Ah）
```

即“当前循环可充电容量 / 标称容量”，对应 MATR 的 Qc、
SNL/HUST pkl 的 `charge_capacity_in_Ah`（逐点累计充电容量取末值）。

明确不使用放电口径：`Qd / Qd(cycle 2)` 是 World Model 论文的口径，
本模块与其无关。

注意（HUST 的固有属性）：HUST 出厂容量约 1.19 Ah > 标称 1.1 Ah，
因此其起始 SOH 约 1.08。这是原论文口径的必然结果，模型可自行学习
该偏移；跨数据集对比 SOH 时需注意此常数差。

## 4. 模型架构（规划）

```
片段 (101, 4)  [I, V, Q, T]
   │
   ▼
共享编码器：Linear(4→128) → ReLU → Linear(128→32)
   │
   ▼
LSTM(input=32, hidden=64)          ← 极化状态/退化状态
   │
   ├── 电压预测头（预训练，稠密监督）
   └── SOH 头 [h; c]（微调，稀疏监督）

物理约束：Arrhenius 正则项
  退化速率 ∝ exp(−Ea / (R·T))
```

训练流程沿用迁移学习：电压预测预训练 → SOH 头微调，
同 `partial_soh` 的 Trainer。

## 4.1 温度通道对预训练/微调的影响（三行消融设计）

加入温度通道是否真的有用，用下面这张表回答（固定 seed、batch、
训练轮数，只开关温度通道与物理约束）：

| 配置 | 预训练 loss | 微调 SOH MAE（主协议） | 结论 |
| --- | --- | --- | --- |
| 3 通道（当前基线） | ？ | ？ | 对照 |
| 4 通道，无物理约束 | ？ | ？ | 温度通道本身有没有用 |
| 4 通道 + Arrhenius | ？ | ？ | 物理约束是否带来额外增益 |

判断标准：

- 若第 2 行预训练 loss 低于第 1 行，说明模型确实把温度用起来了
  （温度影响电压/极化，预训练能捕获）；
- 若第 2 行 SOH MAE 低于第 1 行，说明温度信号传递到了 SOH 回归；
- 若第 3 行进一步下降，说明物理约束在小样本变温条件下有正则价值。

工程注意：温度通道标准化不用全体 z-score（会被 200 块 30°C 恒温电池
主导），改用物理量纲归一化 `T' = (T − 25) / 10`。
